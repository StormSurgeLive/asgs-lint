# asgs-lint

A strict **static** ASGS configuration checker.

`asgs-lint` remains a single Perl-script modulino at `bin/asgs-lint`. It does not source or execute `ASGS_CONFIG`, `PLATFORM_INIT`, `ASGS_PLATFORMS`, or other shell configuration files.

## Quick start

Inside `asgsh` with a profile loaded:

```bash
asgs-lint
```

Or inspect another configuration:

```bash
asgs-lint --config /path/to/config.sh
```

Useful inspection commands:

```bash
asgs-lint --explain
asgs-lint --list rules
asgs-lint --list vars
asgs-lint --list disallowed
perldoc bin/asgs-lint
```

## Current checks

The maintained rule summary is generated by:

```bash
asgs-lint --list rules
```

Current rule families include configuration-file safety, required variables, forcing compatibility, scenario-package structure, Wind10m behavior, CPU capacity, `SERQUEUE_NTASKS`, platform provenance, startup/hotstart consistency, runtime executable availability, wave settings, vortex-model compatibility, and trigger/source compatibility.

### `SERQUEUE_NTASKS`

`SERQUEUE_NTASKS` is optional. If defined, it must be an integer in the range `1..PPN`, using the effective statically derived `PPN`.

### Wind10m

When:

```bash
createWind10mLayer=yes
```

`SCENARIOPACKAGESIZE` must not be actively set and explicit `*Wind10m` forecast scenarios are rejected as obsolete.

### Scenario packages

The linter finds `case $si in` directly; it no longer depends on `SCENARIOPACKAGESIZE` to locate the scenario package. It checks conventional hindcast/nowcast cases, contiguous forecast indices, duplicate/missing scenario assignments, wildcard handling, and conservative forcing/scenario compatibility.

### Platform definitions

If `PLATFORM_INIT` is defined, its file is parsed statically. Otherwise the linter can inspect legacy `ASGS_PLATFORMS` (normally `$SCRIPTDIR/platforms.sh`) and the matching `init_PLATFORM()` function.

Platform, current-environment, and explicit-config differences are reported as provenance warnings. No platform file is sourced.

## `--explain`

`--explain` provides an interpreted summary of the configuration rather than a raw dump. It covers the resolved platform source, forcing, scenario package, compute layout, and lint findings.

## Tests

```bash
prove -lv t
```

The tests include a safety regression proving that shell command substitution inside a platform definition is not executed.

## Agent/developer context

Repository-specific implementation context and future static-analysis direction are maintained in `AGENTS.md`. It is intended primarily for coding agents and maintainers; current ASGS code remains authoritative when historical issues, documentation, or configurator templates disagree.

## Static-analysis boundary

The purpose of `asgs-lint` is to derive everything that can be known safely from static inputs and report where those expectations conflict. It deliberately does not execute shell to resolve dynamic values.

Future static-analysis targets include mesh/default package expectations, input-file availability, statefile contents, and derived output-handling expectations.
